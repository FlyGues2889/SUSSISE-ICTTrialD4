## 二、Skills 调用关系

四个 CodeArts Skills 是业务能力的唯一来源，后端路由只做鉴权、参数校验、持久化，不复制专业逻辑。

```
                    ┌──────────────────────────────┐
   用户提交 24 题 ──▶│ posture_assessment           │
                    │ assess_posture(area, answers)│──▶ 总分 / 六维度 / 问题点
                    └──────────────┬───────────────┘
                                   │ risk_level + red_line_hit
                    ┌──────────────▼───────────────┐
                    │ safety_check                 │
                    │ check_safety(...)            │──▶ 四档 risk_grade / 就医提示
                    └──────────────┬───────────────┘
                                   │
   推荐请求 ────────────────────────▼───────────────
                    ┌──────────────────────────────┐
                    │ plan_matcher                 │
                    │ match_plans(all, risk, area, │──▶ Top-3 + 匹配度
                    │   duration, scene)           │
                    └──────────────────────────────┘

   问答请求 ────────▶ qa_responder.respond_qa()
                     字符二元组重合度召回 + 阈值判定 ──▶ 命中 / 无法回答
                                              │ 置信度 < 0.25
                                              ▼
                     app/services/ai.py（可选，AI_PROVIDER=huawei）
                     华为云 AI 兜底 ──▶ 超时/未配置则回退固定拒答文案

   离线构建 ────────▶ generate_plans.generate_plans()
                     3 部位 × 3 场景 × 4 时长 = 36 方案 SQL
```

调用方向是单向的：`plan_matcher` 读取 `safety_check` 产出的 `risk_level`，自身不判断安全；`qa_responder` 不产出健康建议之外的诊断结论，超出知识库范围时由服务层决定交给 AI 兜底或明确回答"无法回答"。AI 调用不在 Skill 内，Skill 仍是可离线单测的纯函数。

## 三、一次完整闭环的数据流

```
① POST /api/assessment
   answers(24 项) ─▶ assess_posture ─▶ check_safety ─▶ 写 assessment 表
                                                      └▶ 返回报告

② GET  /api/plans/recommend?area=&duration=&scene=&risk_level=
   cache 命中 ─▶ 直接返回
   cache 未命中 ─▶ 查 exercise_plan(36) + custom_plan ─▶ match_plans
                ─▶ 标记 is_favorite ─▶ 回写缓存 300s

③ POST /api/training
   plan_id + 完成动作数 ─▶ 写 training_log ─▶ 失效 user:streak:{uid}

④ GET  /api/training/stats | /streak
   ─▶ 周统计 / 月统计 / 连续打卡（本地日历日计算）

⑤ GET  /api/assessment/history
   ─▶ 每条含 total_score + risk_level + risk_grade ─▶ 前端画趋势折线
```

## 四、架构说明（约 200 字）

系统采用"静态前端 + 单体 API + 外置专业能力"的三层结构。前端是 Vue3 单页应用，全部图表用 SVG 与 CSS 手绘，构建后由 Nginx 直接托管，不依赖任何第三方图表库。后端是 FastAPI 单体服务，按认证、评估、方案、训练、提醒、问答拆成六个路由模块，四个 CodeArts Skills 以纯 Python 模块形式被路由调用，可独立单元测试、可离线批量生成方案 SQL。数据层用 RDS MySQL 单库，Redis 通过 `app/services/cache.py` 统一访问，未配置 `REDIS_URL` 时自动降级为进程内字典，因此小规模演示环境不强制购买 DCS，扩大并发时只需补一个环境变量即可启用缓存。整套服务用 systemd 常驻、Nginx 反代，单台 2C4G ECS 即可承载演示与初期用户。

## 五、关键设计取舍

| 取舍点 | 选择 | 原因 |
|---|---|---|
| 前端图表 | 纯 SVG/CSS | 需求只有双折线与占比条，引入图表库会增加约 300KB 体积，且与"无阴影、无渐变"的视觉约束冲突 |
| Skills 形态 | 纯函数 Python 模块 | 可被 FastAPI 同步调用，也可被脚本批量调用生成 SQL，不绑定智能体运行时 |
| 缓存 | 可选 Redis + 内存降级 | 演示环境可零成本运行，生产扩容只需改环境变量 |
| 评估与安全 | 拆成两个 Skill | 评分回答"有多严重"，安全回答"能不能练"，职责不同、判定阈值不同 |
| 自定义方案 | 独立表 + ID 偏移段 | 用户自建方案与官方 36 方案隔离，官方方案更新不覆盖用户数据 || 问答 | 检索式优先 + AI 兜底 | 命中答案可追溯到知识库条目；仅未覆盖时调用华为云 AI，提示词禁止诊断，AI 不可用则回退拒答文案 |
