# 运动方案库文档

**项目名称**：久坐肩颈腰背科学运动干预助手
**版本**：v1.0
**数据规模**：36 个官方方案｜36 个去重动作｜243 条方案-动作条目｜9 条可查证机构指南

---

## 一、方案库要解决什么问题

市面上不缺拉伸动作，缺的是**在正确的时间给出正确的那三个动作**。一个坐了一整天、肩颈已经发紧的办公室工作者，真正需要的不是"颈椎康复训练大全"，而是"现在，在工位上，不用换衣服，三分钟，做哪几个动作"。

方案库因此不是动作的集合，而是**约束条件下的选择结果**。我们把约束显式化为三个维度：部位、时长、场景。这三个维度穷举出 36 种组合，每种组合对应一个可直接执行的方案。

第四个隐含的维度是**风险等级**。它不参与组合，而是作为过滤条件：高风险用户不进入方案推荐流程，先走就医提示。

## 二、三维矩阵

| 维度 | 取值 | 设计依据 |
|---|---|---|
| 部位 | 肩颈 `neck`／腰背 `back`／全身 `full` | 与评估量表的两套 12 题一一对应，评估结论可以直接映射到方案 |
| 时长 | 3／5／10／15 分钟 | 工位场景中用户能承诺的时间档位；3 分钟对应"接水间隙"，15 分钟对应午休 |
| 场景 | 办公桌前 `desk`／站立休息 `standing`／居家 `home` | 决定动作是否需要站立、是否需要地面空间；办公桌前方案不允许躺卧 |

3 × 3 × 4 = 36 个方案，全部显式生成、逐条落库，不做运行时拼接。这样做的好处是每个方案都可以被人工审阅、可以被单独修改、可以被单独引用，而不是由算法临时组合出一个用户无法预期的动作序列。

## 三、动作池

36 个去重动作，按主目标部位归组：

**肩颈组**（主导动作）
颈部前屈后伸、颈部左右侧屈、颈部旋转、颈部环绕、颈部全方位活动、颈部全方位热身、颈部活动、颈部等长收缩、肩部环绕、肩部深度环绕、肩胛骨收缩、肩胛骨强化、靠墙天使、上背部伸展、胸部开合

**腰背组**（主导动作）
坐姿猫牛式、猫牛式、猫牛式热身、坐姿扭转、腰部扭转、腰部前屈、腰部前屈后伸、骨盆前后倾、侧腰拉伸、臀桥、婴儿式、婴儿式放松、鸟狗式、死虫式

**通用/衔接动作**
深呼吸、深呼吸放松、站姿伸展、站姿前屈、全身伸展、全身关节活动、全身关节热身

每个动作包含四个字段：

| 字段 | 示例 | 用途 |
|---|---|---|
| `name` | 颈部左右侧屈 | 跟练页标题、动作池选择项 |
| `duration_sec` | 30 / 40 / 60 | 跟练倒计时长度，随时长档递增 |
| `description` | 耳朵向肩方向倾斜，不耸肩，左右各一次 | 跟练页正文，说明怎么做 |
| `tips` | 感受颈部侧面拉伸 | 跟练页提示，说明注意什么 |

四个字段都是必填。`tips` 不是重复 `description`，而是专门写**容易做错的地方**——"不耸肩"、"不过度仰头"、"幅度由小到大"这类纠正性提示，是方案质量的关键差异点。

## 四、方案结构

每个方案记录以下信息：

```
name              方案名称，如"肩颈办公桌前 3 分钟"
target_area       neck / back / full
scene             desk / standing / home
duration_min      3 / 5 / 10 / 15
suitable_level    适用风险等级，如 "low,medium"
contraindication  禁忌说明，高风险用户命中即排除
goal              方案目标，如"缓解颈部僵硬"
movements[]       有序动作序列（引用动作池 + 该方案内的秒数）
```

`suitable_level` 与 `contraindication` 是方案库与安全模块的连接点。低风险用户可以看到全部方案；中风险用户只看到标注了 `medium` 的方案；一旦 `check_safety` 判定为高风险，`contraindication` 非空的方案全部排除，且推荐接口不会被业务层放行。

## 五、匹配算法

匹配分四步，全部可解释：

**第一步，硬过滤。** 风险等级不在 `suitable_level` 内的方案直接剔除；高风险时剔除所有带 `contraindication` 的方案。硬过滤的结果是"不该出现的方案根本不出现"，而不是"出现了但排在后面"。

**第二步，加权打分。**

| 项 | 权重 | 说明 |
|---|---|---|
| 部位命中 | 0.4 | 目标部位完全一致得满分；全身方案得 0.2 |
| 时长接近 | 0.3 | 完全一致得满分；不一致时按 `1 - |差值| / 15` 线性衰减 |
| 场景一致 | 0.2 | 一致得分，不一致为 0 |
| 基础分 | 0.1 | 保证任何通过硬过滤的方案都有非零分 |

**第三步，排序取前三。** 返回 Top-3，每条带 `match_score`（0–1 之间，保留两位小数）。

**第四步，合并用户自定义方案。** 用户自建方案与官方方案一起参与打分排序，并标记 `is_favorite`，让"我自己组的方案"不会因为排序被淹没。

这个算法刻意保持简单。理由是：用户需要能理解"为什么推荐这个"，权重表可以原样展示给用户；引入协同过滤或向量召回会让推荐理由无法解释，而健康类产品的推荐理由必须可解释。

## 六、内容溯源

方案库中的每一条健康主张都对应到可查证的机构来源，共 7 个来源、9 条指南条目，覆盖 WHO、NHS、CSP、CSEP、HHS：

| 指南条目 | 机构 | 在产品中的作用 |
|---|---|---|
| 任何数量的身体活动都比没有好，所有年龄组都应限制久坐时间 | WHO 2024 | 首页与报告页的核心主张 |
| 成人每周至少 150 分钟中等强度活动 | WHO | 报告中长期目标说明 |
| 强健肌肉对每个人都有好处 | WHO | 支持抗阻类动作（臀桥、鸟狗式）出现在方案中 |
| 颈部疼痛的治疗以主动活动与姿势调整为主 | CSP | 支持肩颈方案以主动活动而非被动牵拉为主 |
| 腰痛患者应保持活动，避免长期卧床 | NHS | 支持腰背方案在急性期仍给出低强度活动 |
| 24 小时活动指南：限制久坐、增加轻度活动 | CSEP | 支持"碎片化多次"而非"一次长练"的方案设计 |
| 美国身体活动指南：减少久坐，任何强度都有益 | HHS | 支持 3 分钟档方案的存在合理性 |

用户在报告页、指南页都可以展开查看条目原文与链接。**这是本项目与其他健康类产品最直接的区别：建议不是产品经理写的，是可以点开核对原文的。**

## 七、自定义方案

用户可以在动作池中自选 2–6 个动作，组合成个人方案。约束如下：

- 部位从 `neck` / `back` / `full` 中选一个，动作池随之过滤
- 时长从 3 / 5 / 10 / 15 中选一个
- 场景从三个中选一个
- 自定义方案使用独立的 ID 段（从 `900000` 起），与官方方案不在同一区间
- 自定义方案与收藏关系存在独立表中，官方方案更新时不会覆盖用户数据

自定义方案同样参与推荐打分，排在官方方案之后或之前取决于匹配度，不做人为降权。"用户自己组的方案更容易坚持"是产品判断，因此不惩罚它。

## 八、质量标准与已知局限

**我们做到的：**
- 36 个方案逐条人工审阅，动作顺序遵循"激活 → 拉伸 → 放松"的通用原则
- 每个动作有明确的秒数、要领、易错提示
- 高风险用户不进入推荐流程，不存在"先推荐再提示"的顺序问题
- 所有健康主张可溯源到机构原文

**我们尚未做到的（如实说明）：**
- **没有做临床验证。** 评估模型与方案库是筛查与自助工具，不是诊断工具，不能替代医生判断
- **不做个体化剂量。** 目前按风险等级与三维条件给出方案，没有根据年龄、体重、既往伤史调整动作强度
- **动作无视频。** 用文字要领 + 倒计时替代演示视频，降低体积但提高了理解门槛
- **未做长期效果随访。** 趋势数据来自用户自评量表，不是客观功能测量

这些局限已写入申报书的"后续计划"：与康复机构合作做对比研究、引入康复师复核通道、补充动作演示资源。

## 九、维护方式

方案库的源数据在 `skills/generate_plans.py` 的 `MOVEMENT_TEMPLATES` 中，以 `(部位, 时长)` 为键组织。修改动作或方案后执行：

```bash
python skills/generate_plans.py
# 生成方案 SQL，覆盖 exercise_plan / plan_movement
```

前端 Mock 模式的方案数据由 `project/frontend/src/mock/plans.js` 从同一份模板生成，因此演示环境与线上环境看到的方案完全一致，不存在两份内容不同步的问题。
