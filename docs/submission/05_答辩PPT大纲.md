# 答辩 PPT（10 页）

**项目名称**：久坐肩颈腰背科学运动干预助手
**团队**：SUS SISE｜华为 ICT 大赛 · 创新赛道
**汇报时长**：8 分钟（每页 45–55 秒）
**设计约束**：黑白灰 + 单一绿色强调色，无阴影无渐变，每页只讲一个判断

---

## 第 1 页｜封面

**标题**：知道该动，但不知道动什么
**副标题**：久坐肩颈腰背科学运动干预助手
**页脚**：SUS SISE｜华为 ICT 大赛创新赛道

> 口播（20 秒）：我们的项目解决一个具体场景——每天坐八小时的人，知道该起来动，但不知道该动哪几个动作、动多久、什么情况下不能动。今天我们用一个能跑通的完整产品回答这三个问题。

---

## 第 2 页｜痛点：三重空白

**主标题**：四类产品，没有一个回答"我该怎么办"

| 现有产品 | 缺什么 |
|---|---|
| 久坐提醒类 | 只提醒，不评估，不知道提醒之后做什么 |
| 健身跟练类 | 课程为健身设计，与工位、3 分钟碎片时间脱节 |
| 康复指导类 | 需要线下就诊，没有可自助执行的日常方案 |
| 颈椎自测类 | 给总分不给判断，无法区分"能练"与"该就医" |

**底部一句**：四个缺口其实是同一个问题：**专业判断没有产品化**。

> 口播（50 秒）：我们把市面上的产品分成四类。提醒工具只负责叫醒你；健身应用给的是 40 分钟课程，和工位对不上；康复指导要线下就诊；自测工具只给一个分数。四类产品合起来，仍然没有任何一个能告诉用户：你现在有多严重、今天该做哪三个动作、什么情况下不能练。

---

## 第 3 页｜解决方案：一个闭环

**主标题**：从一次评估开始，到一条下降的趋势线结束

**流程条**（横向五段）：
评估 24 题 → 报告 + 依据 → 三维方案匹配 → 跟练打卡 → 趋势追踪

**三句话说明**：
- 首次进入只做一件事：评估。不做注册表单。
- 报告只给一个主动作：去选方案。
- 首页只留今天建议和连续打卡。

**右下角数据**：36 个方案｜36 个动作｜9 条机构指南

> 口播（50 秒）：产品的结构是刻意收窄的。首次进入只做评估，24 题一题一屏；报告只推一个动作，去选方案；首页只留今天建议和打卡进度。我们不做功能齐全的健康 App，我们做一个用户能走完一遍的闭环。走完一遍之后，他会看到一条下降的趋势线——这就是留下来的理由。

---

## 第 4 页｜评估模型：六维度加权

**主标题**：把"颈椎不好"拆成可量化的六件事

**图示**：六维度权重条形（疼痛频率 1.0 / 僵硬 0.8–1.0 / 活动受限 1.0 / 姿势习惯 0.6 / 神经症状 1.0 / 功能影响 0.8）

**关键数字**：
- 肩颈 12 题 + 腰背 12 题，四档选项 0–3 分
- **单侧满分 36.6 分**
- 四档分级：低 < 12.81｜中低 < 18.3｜中高 < 23.79｜高 ≥ 23.79

**为什么这样设计**：分数用于纵向对比（同一个人前后两次），等级用于决定推荐什么强度的方案。

> 口播（50 秒）：评估不是把题目加起来除以总数。六个维度各有权重，神经症状和活动受限权重最高，因为这两项直接决定能不能练。单侧满分 36.6 分，分四档。这里有一个设计取舍：分数主要不是用来和別人比，而是同一个人前后对比——所以趋势图比总分更有意义。

---

## 第 5 页｜安全边界：我们敢拒绝用户 ★

**主标题**：宁可少一个用户，不冒一次风险

**触发条件**：
- 红线题命中 ≥ 2 项（放射性疼痛、肢体麻木无力、夜间痛醒等）
- **或**总分 ≥ 23.79

**命中后的行为**：
1. 报告顶部出现就医提示，说明需要排查的原因
2. **方案推荐入口直接拦截**
3. 不输出任何训练动作

**对照**：同类产品通常只在页面底部写一行"如有不适请就医"。

> 口播（55 秒）：这是产品和健身类应用最大的差别。当用户勾选出放射性疼痛、肢体麻木、夜间痛醒这类警示信号，我们的做法是不推荐训练，而是明确建议就医，并且拦住方案入口。同类产品一般在页面底部写一行小字免责。我们的判断是：把神经根刺激当肌肉紧张来练，代价太大，这个功能值得牺牲一部分转化率。

---

## 第 6 页｜方案库：三维矩阵

**主标题**：36 个方案 = 3 部位 × 3 场景 × 4 时长

**矩阵图**：

```
           3 分钟   5 分钟   10 分钟  15 分钟
肩颈·办公桌   ✓       ✓        ✓        ✓
肩颈·站立     ✓       ✓        ✓        ✓
肩颈·居家     ✓       ✓        ✓        ✓
腰背·办公桌   ✓       ✓        ✓        ✓
腰背·站立     ✓       ✓        ✓        ✓
腰背·居家     ✓       ✓        ✓        ✓
全身 ×3 场景  ✓       ✓        ✓        ✓
```

**内容来源**：WHO 2020 身体活动与久坐指南、CSEP、NHS、CSP、HHS 共 9 条可查证条目

**另外**：动作池支持用户自建方案（自定义方案与官方方案分表，互不覆盖）

> 口播（50 秒）：方案不是随机的动作合集，是按三个维度穷举的矩阵。每个方案写清动作顺序、每个动作的时长、要领和常见错误。为什么是 3、5、10、15 分钟？因为工位场景里，用户能承诺的时间就是这几个档。另外我们开放了动作池，用户可以自己组方案——用户自己组的方案，往往比我们推的更容易坚持。

## 第 7 页｜技术架构：Skills 是能力的唯一来源

**主标题**：四个 Skill，一套专业逻辑，两种调用方式

**架构缩略图**：SPA → Nginx → FastAPI（6 路由）→ Skills（4 个）→ RDS / Redis（可选）

**Skill 与职责**：
| Skill | 职责 | 调用方 |
|---|---|---|
| `posture_assessment` | 六维度加权评分 | 评估接口 |
| `safety_check` | 四档分级 + 就医建议 | 评估接口 |
| `plan_matcher` | 三维匹配 + 匹配度 | 推荐接口 |
| `qa_responder` | 知识库召回 + 拒答 | 问答接口 |

**关键点**：路由只做鉴权与持久化，不复制业务逻辑；Skill 是纯函数，可单测、可离线批量生成 SQL。

> 口播（50 秒）：技术上的核心选择是把专业逻辑全部收进四个 Skill，后端路由只负责鉴权和落库。这样做的好处是：同一个评分函数，既能在用户提交评估时实时调用，也能在离线脚本里批量验证；改一次权重，前端和后端同时生效，不会出现两套逻辑算出两个分数。Redis 是可选优化，不配也能跑，配了只加一个环境变量。

## 第 9 页｜创新性与专业壁垒

**主标题**：场景 + 技术 + 专业的三重叠加

**三点**：
1. **场景创新**：不做完整课程，做碎片化方案矩阵，动作全部可在工位完成、不需要换衣、不需要器械
2. **安全创新**：把"该不该练"独立成一个判断环节，并让它有拦截权
3. **专业壁垒**：团队成员来自运动康复相关专业，评估维度与红线标准来自可查证的机构指南，不是产品经理凭感觉设定

**佐证**：9 条机构指南全部标注出处，用户可在产品内查看原文条目

> 口播（50 秒）：创新不在于用了多少新技术。我们的第一个创新是场景——把方案切到 3 分钟这个颗粒度；第二个是安全——把"该不该练"独立出来，并且赋予它拦住推荐入口的权力；第三个是专业壁垒，我们的评估维度和红线标准都能追溯到机构指南原文，用户在报告页可以直接看到出处，这一点很难靠拍脑袋复制。

## 第 10 页｜应用价值与路线图

**主标题**：个人版 → 企业员工健康版

**价值三段**：
| 对象 | 价值 |
|---|---|
| 个人用户 | 零成本 Web 端，无需下载，三步得到可执行方案 |
| 企业 | 员工健康管理模块，可对接体检与工位改造数据 |
| 专业机构 | 评估结果可作为线下就诊前的初筛材料 |

**路线图**：
- 已完成：评估闭环、36 方案、安全拦截、追踪趋势、指南溯源、问答
- 下一步：企业版数据看板、可穿戴设备久坐时长接入、康复师人工复核通道

**结尾一句**：让"该动了"变成"知道怎么动"。

> 口播（45 秒）：短期看，这是一个个人能直接用的免费 Web 产品。中期看，最有价值的是企业场景——员工健康管理里的颈椎腰椎问题，是最容易量化投入产出的一块。长期看，评估结果可以成为线下就诊前的初筛材料，帮用户少跑一次门诊。我们的目标是让"该动了"这句话，变成"知道怎么动"。

## 附：答辩常见追问准备

| 追问 | 回答要点 |
|---|---|
| 评估模型有临床验证吗 | 明确说明**未做临床验证**，是筛查工具不是诊断工具，四档分级用于方案强度选择；后续计划与康复机构合作做对比研究 |
| 和 Keep、小米健康有什么不同 | 他们做课程，我们做碎片场景 + 拦截机制；我们不比内容量，比"该不该练"的判断 |
| 用户凭什么坚持 | 趋势线 + 连续打卡 + 3 分钟低门槛；不承诺留存率数字 |
| 商业化怎么做 | 个人版免费，企业版按员工数订阅；不做医疗诊断收费 |
| 数据隐私 | 不收集手机号，注册即发令牌；密码 bcrypt；健康数据仅本人可见 |
| 为什么不用大模型直接问答 | 健康建议需要可溯源与拒答能力，所以检索式问答优先，命中的答案能给出确切出处；只有知识库未覆盖时才交给华为云 AI 兜底，提示词硬性禁止诊断、危险信号直接建议就医，AI 不可用时回退到固定拒答文案 |
