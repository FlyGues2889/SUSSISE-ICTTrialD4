### 加权总分公式与风险阈值推导
- 公式：`total_score = round(Σ score_i × weight_i)`
- 每区权重和 = 1.0×6 + 0.8×4 + 1.5×2 = 12.2
- 满分 `max_score = 3 × 12.2 = 36.6`
- `low < max×25% = 9.15`
- `medium < max×55% = 20.13`
- `high ≥ 20.13 或红线命中`
- total_score 四舍五入取整，与 DB int 字段兼容

### problem_points 新排序逻辑
按维度聚合加权得分 `dim_score = Σ(score×weight)`，维度满分 `dim_max = Σ(3×weight)`。
维度问题阈值 = `dim_max × 40%`，超过即列为问题点，按 `dim_score` 降序输出对应 DIMENSION_LABELS。
阈值由代码动态计算（如神经症状 dim_max=9.0 阈值3.6；姿势习惯 dim_max=4.8 阈值1.92）。

## 评估交互与阈值调优（2026-10-30）

### 交互改造
- 选项按钮由胶囊按钮改为圆形 Likert 圆点（4 个，左→右分值 0→3，颜色灰→绿→橙→红表示严重递增），两端锚点标签「无」「持续」，选中圆实心放大并显示当前档位文字。
- 改动位置：`Assessment.vue` 模板（内联 likert 结构）+ 样式 + 移除 `AppRadioGroup` 引用。`AppRadioGroup` 组件本身保留不动。

### 题干修正
- N9「最近一周颈部疼痛持续的天数」→「最近一周颈部疼痛是否持续存在」（天数是连续量，不适用 4 档频率）
- B12「改变体位后腰背疼痛是否缓解」→「久坐后腰背疼痛是否难以自行缓解」（原题语义反向，高分反被判高风险）

### 阈值与红线调优
用户反馈「选几个偶尔就提示就医」，根因：红线题 ≥1 即触发 + high 阈值偏低（55% 满分）。
- 红线触发阈值由 ≥1 改为 **≥2**（经常及以上才强制就医；偶尔计入加权分但不直接触发就医）。
- 风险阈值比例由 25%/55% 改为 **35%/65%**：low < 12.81，medium < 23.79，high ≥ 23.79 或红线命中。
- 同步修改 `skills/posture_assessment.py` 与 `frontend/src/mock/skills.js`。

### 样例验证
| 样例 | risk | score | 红线 |
|------|------|-------|------|
| 全偶尔(12题×1) | low | 12 | False |
| 6偶尔6无 | low | 6 | False |
| N5=偶尔(1) | low | 2 | False |
| N5=经常(2) | high | 3 | True |

结论：偶尔档不再轻易触发就医，需经常/持续档或加权总分达 65% 满分才进 high。

### 对 PRD 的影响
PRD §2.1 风险等级判定规则表（红线 ≥1、总分 6/13 阈值）与当前实现已不一致，需后续同步更新为：红线 ≥2、加权总分按 35%/65% 满分切分。

## 四档风险评级（2026-10-30）

### 目标
将原「中风险」再细分为「中低风险 / 中高风险」，形成 low / medium_low / medium_high / high 四档展示，使评估反馈更细腻。

### 设计取舍
`risk_level`（low/medium/high）被 `plan_matcher.py`（LEVEL_ORDER、suitable_level 匹配）、`safety_check.py`、DB `assessment.risk_level`、`Home.vue`/`Plans.vue` 推荐链路依赖。若直接把 risk_level 改成四档会连锁破坏方案匹配与安全判定，且 DB 列 `VARCHAR(10)` 放不下 `medium_high`（11 字符）。
故采用**兼容方案**：`risk_level` 保持三档契约不变，新增 `risk_grade` 四档字段仅用于展示；medium_low / medium_high 均映射为 risk_level=medium，推荐与安全逻辑完全不变。

### 分档规则
- `MEDIUM_SPLIT = (LOW_THRESHOLD + HIGH_THRESHOLD) / 2 = (12.81 + 23.79) / 2 = 18.3`
- low：总分 < 12.81
- medium_low：12.81 ≤ 总分 < 18.3
- medium_high：18.3 ≤ 总分 < 23.79
- high：总分 ≥ 23.79 或红线命中

### 改动文件
- `skills/posture_assessment.py`：新增 `MEDIUM_SPLIT`，计算 `risk_grade`，`risk_level` 由 grade 映射；返回体新增 `risk_grade`。
- `project/frontend/src/mock/skills.js`：`assessPosture` 同步 `riskGrade` 与映射，返回体新增 `risk_grade`。
- `project/backend/app/routers/assessment.py`：提交接口返回体透传 `risk_grade`（DB 仍只存 risk_level）。
- `project/frontend/src/views/Assessment.vue`：`riskLabel` 改用四档映射（回退 risk_level）、risk-badge class 用 risk_grade、新增 `.medium_low`/`.medium_high` 背景样式、submitAll 结果透传 `risk_grade`。

### 验证
- `python -m py_compile skills/posture_assessment.py` 与 `app/routers/assessment.py`：通过
- `pnpm build`：通过
- 样例：全0→low/low；全偶尔(1)→low/low(12分)；全经常(2,红线置0)→medium/medium_low(18分)；全持续(3)→high/high(37分)

### 对 PRD 的影响
PRD 风险等级表需补充四档展示说明（中风险拆中低/中高，分界 18.3），并注明底层 risk_level 仍为三档、推荐逻辑不变。
