## 1. 角色定位与职责边界

本角色是 3 人团队中**唯一面向"可部署、可演示、可评审、可申报"产出**的角色，统筹华为云部署、演示闭环、申报材料与进度推进，确保最终交付物能让评委在 3 分钟内看到完整干预闭环。

### 1.1 职责边界

| 职责域 | 本角色负责 | 不负责 |
|---|---|---|
| **云部署** | ECS 部署配置、RDS/Redis 实例管理、演示环境搭建 | 前后端代码开发（工程角色） |
| **演示** | Demo 现场脚本、流程编排、录屏兜底、演示数据预置 | 演示环境代码部署（工程角色） |
| **文档** | 申报书、答辩 PPT、技术架构图、CodeArts 使用说明 | Skills 业务规则文档（专业内容角色） |
| **测试** | 验收测试、演示路径手测、缺陷登记 | 单元测试（工程角色） |
| **进度** | 里程碑跟踪、风险登记、跨角色协调 | 各角色内部任务排期 |

### 1.2 不可越界原则
- 不改上游 PRD 的功能清单和优先级；如需变更，走变更流程。
- 不写代码；提供原型与交互稿，工程角色实现。
- 不替专业内容角色定义评估规则和方案内容。

## 2. 华为云部署需求

### 2.1 资源清单

| 资源 | 规格 | 用途 | 月成本（*推测） |
|---|---|---|---|
| ECS | 云耀 L 实例 2vCPU/2GB/40GB | 前后端部署 + Nginx | ~50-100 元 |
| RDS MySQL | 通用型 2vCPU/2GB/40GB | 数据持久化 | ~100-200 元 |
| DCS Redis | 单机 128MB | 缓存与会话 | ~30-50 元 |
| 合计 | — | — | ~200-350 元/月 |

### 2.2 部署验收标准
1. 在线 URL 可访问，HTTPS 配置完成
2. 核心闭环 3 分钟内走完无报错
3. 演示数据预置完成（1 个中等风险评估结果 + 3 个推荐方案 + 7 天训练记录）
4. ECS 配置自动重启，RDS/DCS 主备规格

## 3. 演示需求

### 3.1 演示闭环脚本

```
[0:00-0:20] 开场：项目定位 — "久坐3亿人的肩颈腰背运动干预"
[0:20-0:50] 注册登录 — 匿名ID一键注册
[0:50-1:50] 体态评估 — 完成肩颈8题+腰背8题，展示评估报告（中风险）
[1:50-2:30] 方案推荐 — 选"3分钟/肩颈/办公桌"，展示3个推荐方案
[2:30-3:00] 方案跟练 — 进入方案详情，展示动作序列，完成打卡
[3:00-3:30] 进度追踪 — 展示打卡天数+周统计
[3:30-4:00] 久坐提醒 — 设置45分钟提醒，展示提醒弹窗
[4:00-4:30] 高风险演示 — 切换高风险评估结果，展示就医提示
[4:30-5:00] 收尾：创新点总结 — "评估→匹配→执行→追踪闭环"
```

### 3.2 演示数据预置规格

| 数据项 | 内容 |
|---|---|
| 演示账号 | 匿名 ID，已完成 1 次中等风险评估 |
| 评估结果 | 肩颈中风险(10分) + 腰背低风险(4分) |
| 训练记录 | 过去 7 天完成 5 次方案，连续打卡 5 天 |
| 提醒设置 | 45 分钟间隔，09:00-18:00 活跃时段 |
| 备用账号 | 1 个高风险评估结果账号（演示就医提示） |

### 3.3 录屏兜底
准备 1 段 5 分钟完整录屏，现场演示失败时播放。录屏需包含所有核心交互的真实操作。

## 4. 申报材料需求

### 4.1 交付物清单

| 序号 | 交付物 | 要点 | 字数/时长 | 截止 |
|---|---|---|---|---|
| 1 | 项目申报书 | 痛点→方案→技术→创新→价值 | 3000-5000 字 | 第 7 周末 |
| 2 | 技术架构图 | 华为云资源拓扑 + Skills 调用关系 | 1 图 + 200 字 | 第 6 周末 |
| 3 | 演示视频 | 完整走通核心闭环 | 3-5 分钟 | 第 7 周末 |
| 4 | 在线演示 URL | 华为云部署可访问 | 持续可访问 | 第 7 周末 |
| 5 | 答辩 PPT | 10 页以内，突出创新性+应用价值 | 10 页 | 第 8 周 |
| 6 | 运动方案库文档 | 专业内容体系说明 | 2000-3000 字 | 第 7 周末 |
| 7 | CodeArts 使用说明 | Skills 设计思路+提效数据 | 500-1000 字 | 第 8 周 |

### 4.2 申报书结构

```
1. 项目简介（500字）
   - 一句话定位 + 目标人群 + 核心能力

2. 创新性论述（1500字，对应60%）
   - 场景创新：三重空白市场（提醒无评估/健身无久坐专项/康复无碎片化）
   - 技术创新：CodeArts Skills 封装运动康复专业能力
   - 方案创新：碎片化场景方案矩阵（36+方案）
   - 专业壁垒：SUS 运动康复专业背景

3. 应用价值论述（1000字，对应40%）
   - 用户价值：3亿+久坐人群，五痛点精准对应
   - 可落地性：MVP可演示，零门槛Web端
   - 可推广性：个人版→企业员工健康版延展

4. 技术方案（800字）
   - 架构图 + 华为云资源 + Skills说明

5. 团队介绍（200字）
   - 三角色分工 + SUS SISE
```

### 4.3 答辩 PPT 结构（10 页）

| 页 | 内容 |
|---|---|
| 1 | 封面：项目名 + 团队 + 单位 |
| 2 | 痛点：三重空白 + 五大痛点 |
| 3 | 方案：四步闭环模型 |
| 4 | 演示：核心流程截图 |
| 5 | 创新：3 个创新点 |
| 6 | 技术：架构图 + 华为云资源 |
| 7 | CodeArts：4 个 Skills 设计 |
| 8 | 专业壁垒：运动康复知识可编程化 |
| 9 | 应用价值：3 亿人群 + 可推广 |
| 10 | 团队 + 致谢 |

### 4.4 三个记忆点（贯穿申报与答辩）

1. **「提醒你该动了 → 告诉你哪里有问题、该怎么动」**
2. **「3 分钟办公椅上的运动康复」**
3. **「运动康复知识可编程化」**

## 5. 进度管理

### 5.1 里程碑跟踪

| 里程碑 | 时间 | 验收标准 |
|---|---|---|
| M1 骨架可运行 | 第 2 周末 | 前后端可启动，数据库可连接 |
| M2 P0功能完成 | 第 5 周末 | 6 个 P0 功能全部可演示 |
| M3 可演示 MVP | 第 7 周末 | 部署上线，闭环走通 |
| M4 全部交付 | 第 8 周末 | 所有交付物完成 |

### 5.2 风险登记

| 风险 | 等级 | 规避方案 |
|---|---|---|
| 专业内容不准确 | 高 | 教师审核 + 教科书依据 + 免责声明 |
| 工期不足 | 高 | P0/P1/P2 严格优先级 + CodeArts 提效 + 并行开发 |
| 创新性表达不充分 | 中 | 三记忆点贯穿 + Skills 深度展示 |
