### 详细分工

#### 角色 A — 专业内容体系（运动康复方向）

**核心职责**：
1. 基于运动康复专业知识，设计体态自评问卷体系（肩颈/腰背两大区域，每区域 8-12 个自评条目，覆盖疼痛频率、僵硬程度、活动受限、姿势习惯四个维度）
2. 编写碎片化运动方案库（按场景分类：办公桌前 3 分钟、站立休息 5 分钟、午间 10 分钟、居家 15 分钟；按部位分类：肩颈、腰背、全身；每个方案含动作序列、时长、注意事项、禁忌人群）
3. 制定安全边界规则（哪些症状提示需要就医、哪些动作不适合特定人群、运动强度递进原则）
4. 利用 CodeArts 智能体辅助生成 Skills 知识文件，将专业内容结构化为可被程序调用的规则库

**协作节点**：
- 与 B 对接：提供结构化方案库 JSON 格式定义，约定评估结果 → 方案推荐的匹配规则接口
- 与 C 对接：提供申报材料中的专业特色文案、演示脚本中的专业亮点话术

**能力假设**：具备运动康复基础知识，不需算法开发能力，主要产出是结构化专业内容

#### 角色 B — 产品功能开发（工程方向）

**核心职责**：
1. 前端：Vue3 + Element Plus 实现四大核心页面（体态评估页、方案推荐页、久坐提醒页、进度追踪页）+ 用户注册登录
2. 后端：FastAPI 实现评估提交、方案查询、提醒设置、进度记录等 API

4. 缓存：Redis 缓存高频方案列表、用户会话状态、热门问答结果
5. 利用 CodeArts 智能体生成后端 CRUD 脚手架、前端页面模板、数据库 DDL

**协作节点**：
- 与 A 对接：接收方案库 JSON 和评估问卷定义，实现方案匹配推荐逻辑
- 与 C 对接：提供可部署的代码包、环境变量配置清单、数据库初始化脚本

**能力假设**：具备 Web 全栈开发基础（Python + Vue），CodeArts 智能体承担 60% 以上重复编码

#### 角色 C — 云部署与演示（产品方向）

**核心职责**：

### 核心加分点设计

#### 创新性加分点（60% 权重）

1. **专业内容 × AI 匹配的独特组合**：市面久坐提醒工具（如番茄钟、站立提醒）仅做定时提醒，不做专业评估和方案推荐；市面健身 App（如 Keep）内容通用化，不针对久坐肩颈腰背专项。本项目以运动康复专业评估问卷为入口，AI 匹配碎片化干预方案，填补"评估 → 干预"闭环空白。

2. **CodeArts Skills 深度应用**：不止用 CodeArts 写代码，更将运动方案匹配逻辑、体态评估评分规则、安全边界判断封装为自定义 Skills，体现"智能体 + Skills"的深度应用模式，而非仅把 CodeArts 当代码生成器。

3. **碎片化场景方案体系**：按时间（3/5/10/15 分钟）× 部位（肩颈/腰背/全身）× 场景（办公桌/站立/居家）三维分类，共 36+ 个方案单元，区别于通用健身 App 的完整课程模式，贴合久坐人群"没时间但需要动"的真实需求。

#### 应用价值加分点（40% 权重）

1. **目标人群规模**：中国久坐人群超 3 亿（上班族 2 亿 + 学生 0.5 亿 + 其他），肩颈腰背不适发生率超 60%，市场基数庞大。

2. **零门槛即用**：无需下载 App、无需穿戴设备、无需注册即可体验评估，Web 端打开即用，降低使用门槛。

3. **健康合规定位**：明确"健康运动指导"而非"医疗诊断"，设置就医提示红线，规避监管风险，增强落地可行性。

### 初赛申报材料核心文案方向

**创新性论述方向**（对应 60%）：
- 主标题建议：「以运动康复专业评估为内核，CodeArts 智能体驱动碎片化运动干预」
- 核心论点 1：首创"体态自评 → AI 方案匹配 → 碎片化执行 → 进度闭环"四步干预模型
- 核心论点 2：CodeArts Skills 封装专业评估规则和方案匹配逻辑，实现"专业知识可编程化"
- 核心论点 3：SUS 运动康复专业背景保证内容专业性和安全边界可靠性

**应用价值论述方向**（对应 40%）：
- 核心论点 1：覆盖 3 亿+ 久坐人群，肩颈腰背健康需求刚性且高频
- 核心论点 2：零门槛 Web 端 + 碎片化方案，匹配"想动但没时间"的真实场景
- 核心论点 3：可从个人版扩展为企业员工健康福利版（B 端延展性）

## 三、具体技术实现方案（初赛 MVP 版）

### 3.1 功能优先级拆解

#### P0 — 初赛必做核心功能（按开发顺序）

| 序号 | 功能 | 说明 | 预估工时 |
|-----|------|------|---------|
| 1 | 用户注册/登录 | 手机号或匿名 ID 注册，JWT 鉴权 | 2 天 |
| 2 | 体态自评问卷 | 肩颈 + 腰背两区域问卷，每区域 8-12 题，提交后生成评估报告（风险等级 + 主要问题点） | 3 天 |
| 3 | 分场景运动方案推荐 | 根据评估结果 + 用户选择场景（时间/部位/场所），匹配推荐 3 个方案，含动作图示说明 | 4 天 |
| 4 | 久坐提醒设置 | 用户自定义提醒间隔（30/45/60/90 分钟），浏览器通知或页面内弹窗 | 2 天 |
| 5 | 训练进度追踪 | 记录每次完成的方案、时长、日期，展示周/月统计和连续打卡天数 | 3 天 |
| 6 | 就医提示红线 | 评估结果达到高风险阈值时，弹出就医建议提示，不提供运动方案 | 1 天 |

#### P1 — 可选扩展功能（时间充裕时做）

| 序号 | 功能 | 说明 |
|-----|------|------|
| 7 | 智能问答 | 基于知识库的常见问题回答（CodeArts Skills 驱动），如"脖子转动有响声正常吗" |
| 8 | 数据可视化 | 体态改善趋势图、部位关注度热力图 |
| 9 | 方案收藏与自定义 | 用户收藏喜欢的方案、调整提醒频率 |

#### P2 — 不做（明确排除）

- 复杂图像识别体态检测（需摄像头 + AI 模型，超出 MVP 范围）
- 硬件设备对接（手环/手表数据同步）
- 社交功能（排行榜/好友/分享）
- 在线直播课程

### 3.2 华为云资源落地明细

#### CodeArts 智能体 + 自定义 Skills

| Skill 名称 | 功能 | 输入 | 输出 |
|-----------|------|------|------|
| `posture_assessment` | 体态评估评分 | 问卷答案 JSON（区域 + 各条目分值） | 风险等级（低/中/高）+ 主要问题点列表 + 建议 |
| `plan_matcher` | 运动方案匹配 | 评估结果 + 场景参数（时间/部位/场所） | 推荐方案列表（3 个，按匹配度排序） |
| `safety_check` | 安全边界检查 | 评估结果 + 用户基本信息（年龄/既往史） | 安全判定 + 是否需要就医提示 |
| `qa_responder` | 智能问答 | 用户问题文本 | 匹配的知识库答案 + 相关方案推荐 |

**Skills 实现方式**：每个 Skill 为一个 Python 模块，核心逻辑为规则匹配 + 加权评分，不依赖外部 AI 模型。CodeArts 智能体负责生成 Skill 脚手架代码和测试用例，专业内容由角色 A 填写。

#### RDS 数据库设计（6 张核心表）

```sql
-- 1. 用户档案表
CREATE TABLE user (
    user_id        BIGINT PRIMARY KEY AUTO_INCREMENT,
    nickname       VARCHAR(50),
    phone          VARCHAR(20) UNIQUE,
    age            INT,
    occupation     VARCHAR(50),          -- 职业（久坐类型分类）
    history        TEXT,                 -- 既往史（颈腰椎病等）
    created_at     DATETIME DEFAULT NOW()
);

-- 2. 体态评估记录表
CREATE TABLE assessment (
    assessment_id  BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id        BIGINT NOT NULL,
    area           VARCHAR(20) NOT NULL,  -- 评估区域：neck / back / full
    answers        JSON NOT NULL,         -- 各条目答案
    risk_level     VARCHAR(10) NOT NULL,  -- low / medium / high
    problem_points JSON,                  -- 主要问题点
    suggestion     TEXT,
    created_at     DATETIME DEFAULT NOW(),
    INDEX idx_user (user_id)
);

-- 3. 运动方案库表
CREATE TABLE exercise_plan (
    plan_id        BIGINT PRIMARY KEY AUTO_INCREMENT,
    name           VARCHAR(100) NOT NULL,
    duration_min   INT NOT NULL,           -- 时长（3/5/10/15）
    target_area    VARCHAR(20) NOT NULL,   -- neck / back / full
    scene          VARCHAR(20) NOT NULL,   -- desk / standing / home
    movements      JSON NOT NULL,          -- 动作序列（名称+描述+时长+图示URL）
    suitable_level VARCHAR(20),            -- 适合风险等级
    contraindication TEXT,                 -- 禁忌人群说明
    created_at     DATETIME DEFAULT NOW()
);

-- 4. 训练记录表
CREATE TABLE training_log (
    log_id         BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id        BIGINT NOT NULL,
    plan_id        BIGINT NOT NULL,
    duration_actual INT,                   -- 实际执行时长
    completed      BOOLEAN DEFAULT TRUE,
    created_at     DATETIME DEFAULT NOW(),
    INDEX idx_user_date (user_id, created_at)
);

-- 5. 久坐提醒设置表
CREATE TABLE reminder_setting (
    reminder_id    BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id        BIGINT NOT NULL UNIQUE,
    interval_min   INT DEFAULT 45,         -- 提醒间隔
    active_hours   VARCHAR(50),            -- 活跃时段（如 09:00-18:00）
    enabled        BOOLEAN DEFAULT TRUE,
    updated_at     DATETIME DEFAULT NOW()
);

-- 6. 知识库表（智能问答用）
CREATE TABLE knowledge_base (
    kb_id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    question       VARCHAR(200) NOT NULL,  -- 标准问题
    answer         TEXT NOT NULL,          -- 标准答案
    keywords       VARCHAR(200),           -- 匹配关键词
    related_plans  JSON,                   -- 关联方案 ID 列表
    category       VARCHAR(50)             -- 分类（肩颈/腰背/习惯/安全）
);
```

#### Redis 缓存设计

| 缓存 Key 模式 | 内容 | TTL | 解决的问题 |
|--------------|------|-----|-----------|
| `plans:hot:{area}:{duration}` | 热门方案列表（按部位+时长） | 1 小时 | 避免每次推荐都查 RDS 方案库 |
| `qa:cache:{question_hash}` | 问答结果缓存 | 24 小时 | 相同问题不重复匹配知识库 |
| `user:session:{user_id}` | 用户会话状态（当前评估进度） | 30 分钟 | 问卷分步提交时保存中间状态 |
| `user:streak:{user_id}` | 连续打卡天数 | 24 小时 | 避免每次查训练记录表计算 |

### 3.3 前端与部署方案

#### 前端技术选型

- **框架**：Vue 3 + Vite（轻量、构建快）
- **UI 库**：Element Plus（组件丰富、文档完善）
- **状态管理**：Pinia（轻量，MVP 够用）
- **HTTP**：Axios（统一拦截、错误处理）
- **图表**：ECharts（进度追踪可视化，P1 功能用）
- **设计风格**：黑白灰极简配色 + 卡片式布局，强调专业感和清爽感

#### 页面规划（5 个核心页面）

1. **首页/评估入口**：功能导航 + 快速评估入口 + 今日推荐
2. **体态评估页**：分步问卷（肩颈区 → 腰背区）→ 评估报告展示
3. **方案推荐页**：场景选择器（时间/部位/场所）→ 方案卡片列表 → 方案详情（动作序列）
4. **提醒与追踪页**：提醒设置 + 训练日历 + 统计数据
5. **我的页**：评估历史 + 训练记录 + 个人信息

#### 华为云部署流程

```
1. ECS 服务器申请（2 核 4G，CentOS）
   ↓
2. RDS MySQL 实例创建 + 导入 schema.sql
   ↓
3. Redis 实例创建
   ↓
4. ECS 安装 Docker + docker-compose
   ↓
5. 后端打包 Docker 镜像（FastAPI + uvicorn）
   ↓
6. 前端 pnpm build → dist 静态文件
   ↓
7. Nginx 反向代理：/ → 前端 dist，/api → 后端 FastAPI
   ↓
8. 配置 HTTPS（华为云 SSL 证书）
   ↓
9. 验证演示环境可访问
```

## 五、核心风险与规避方案

### 风险 1：专业内容准确性风险

**风险描述**：运动方案如果不够专业或存在安全隐患，可能影响评审对"专业壁垒"的评价，甚至产生健康误导风险。

**规避方案**：
1. 角色 A 依托SUS 运动康复专业课程知识，所有方案基于教科书和临床指南编写，不凭空创造动作
2. 设置三道安全防线：① 每个方案标注禁忌人群 ② 评估高风险用户不推荐方案只提示就医 ③ 全局设置"本工具提供健康运动指导，不替代医疗诊断"免责声明
3. 邀请专业教师审核方案库（利用学院资源），在申报材料中注明"经运动康复专业审核"

### 风险 2：2 个月工期不足风险

**风险描述**：3 人团队 + 2 个月周期，需完成专业内容 + 全栈开发 + 云部署 + 申报材料，工期紧张。

**规避方案**：
1. 严格按 P0/P1/P2 优先级开发，P0 六个功能确保完成，P1 视余量追加，P2 明确不做
2. CodeArts 智能体承担 50-60% 重复编码（CRUD 脚手架、前端模板、测试用例），人工聚焦核心逻辑和专业内容
3. 阶段 1-2 并行推进：A 写内容不依赖 B 的代码，B 用 Mock 数据开发不依赖 A 的终稿，C 同步准备云环境
4. 第 6 周设为"功能冻结"节点，之后只修 Bug 不加功能

### 风险 3：创新性表达不充分风险

**风险描述**：项目功能（评估 + 推荐 + 提醒 + 追踪）拆开看每个都不复杂，评审可能认为"技术含量不高"，影响创新性 60% 得分。

**规避方案**：
1. 创新性不押注在单点技术复杂度上，而是押注在"专业内容 × AI 匹配 × 碎片化场景"的组合创新上——市面无同类产品做这个闭环
2. 深度展示 CodeArts Skills 应用：不是简单用 CodeArts 写代码，而是将专业评估规则和方案匹配逻辑封装为 Skills，体现"专业知识可编程化"的创新思路
3. 申报材料和答辩 PPT 中，用"四步干预模型"框架包装：体态自评 → AI 方案匹配 → 碎片化执行 → 进度闭环，强调"闭环"而非单点功能
4. 突出专业壁垒：SUS 运动康复专业背景是其他参赛团队无法复制的差异化优势，在申报材料中重点呈现
