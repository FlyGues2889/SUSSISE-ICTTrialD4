## 1. 项目概述

### 1.1 背景

中国久坐人群超 3 亿（上班族约 2 亿 + 大学生约 0.5 亿 + 其他约 0.5 亿），肩颈不适发生率 60%-80%，腰背不适发生率 40%-60%（*推测，基于流行病学调查共识）。久坐对肩颈腰背的损害是渐进性的——从短期可逆的肌肉疲劳，到中期姿势变形，再到长期慢性疼痛。

当前市场存在三重空白：
- **久坐提醒工具**（番茄钟、站立提醒等）只提醒不评估不推荐，用户知道该动了但不知道怎么动；
- **通用健身 App**（Keep 等）不针对久坐肩颈腰背专项，且课程 15-60 分钟不适合碎片化场景；
- **运动康复**门槛高费用高，适合治疗不适合日常预防。

**「久坐专项 + 专业评估 + 碎片化方案 + 零门槛即用」当前无产品覆盖，市场空白明确。**

### 1.2 一句话定位

面向全民久坐人群的**轻量化健康运动指导工具**：体态自评 → AI 匹配碎片化运动方案 → 久坐提醒 → 进度追踪，把运动康复专业知识从"到医院才能获得"变为"打开网页即用"。

（技术版本：「体态评估引擎 + 分场景方案匹配 + 安全边界判断」，纯软件 Web 端、零门槛即用、不依赖硬件。）

### 1.3 项目目标（初赛）

1. 交付一套**可在华为云在线访问、可现场演示**的 Web 原型。
2. 锁定**1 个完整闭环**（注册 → 体态评估 → 方案推荐 → 执行方案 → 进度追踪），全流程可演示。
3. 满足赛题硬性要求：基于华为云 CodeArts 智能体 + 自定义 Skills 开发，使用 RDS 持久化、Redis 缓存，部署华为云。
4. 覆盖 **36+ 碎片化运动方案**（4 时长 × 3 部位 × 3 场景），适配久坐全场景碎片化运动需求。

### 1.4 赛题硬性要求对照

| 赛题要求 | 本项目落点 | 深度体现 |
|---|---|---|
| CodeArts 智能体 + 自定义 Skills | 4 个 Skill：posture_assessment / plan_matcher / safety_check / qa_responder | 自定义 Skills 为最高加分项，封装运动康复专业能力 |
| RDS 存储 | 用户档案、评估记录、运动方案库、训练记录、提醒设置、知识库 | MySQL 8.0，JSON 字段灵活存评估答案与动作序列 |
| Redis 缓存 | 热门方案缓存（Hash）、问答缓存（String）、会话状态（Hash）、打卡天数（String） | 仅做缓存与会话，主数据落 RDS，不过度设计 |
| 华为云部署、在线演示 | ECS 单机部署 + RDS/DCS 托管，现场 Demo | 月成本约 200-350 元（*推测以官网为准） |

> 评审权重：**创新性 60% + 应用价值 40%**。创新性是决定性得分项，本项目以「三重空白场景 + 运动康复专业评估 + CodeArts Skills 深度应用」拿创新分。

### 1.5 合规边界

本项目定位为**健康运动指导工具**，不涉及疾病诊断与治疗。全局设置免责声明："本工具提供健康运动指导，不替代医疗诊断，持续不适请及时就医。"评估结果达到高风险阈值时，强制弹出就医提示，不推荐运动方案。

## 2. 目标用户与核心场景

### 2.1 用户画像

- **主用户**：20-45 岁久坐人群（程序员、设计师、财务、行政、学生、驾驶员等），每日久坐 6-10 小时，已有肩颈或腰背不适但未到就医程度。
- **用户特征**：想动但没时间、不知道怎么动、怕动错、坚持不下来。
- **使用场景**：办公桌前、工位站立、午休、居家。
- **设备偏好**：手机浏览器为主，PC 浏览器为辅，不愿下载 App。

### 2.2 核心场景（初赛聚焦）

| 场景 | 用户动作 | 期望结果 | 现行痛点 |
|---|---|---|---|
| 首次体态评估 | 完成肩颈+腰背自评问卷（16-24 题） | 生成评估报告：风险等级 + 主要问题点 + 建议 | 不知道哪里有问题、什么程度 |
| 获取运动方案 | 选择场景（时间/部位/场所） | AI 匹配推荐 3 个碎片化方案 | 不知道怎么动、没时间动 |
| 执行方案 | 跟练方案动作序列（3-15 分钟） | 完成打卡、记录训练时长 | 怕动错、无专业指导 |
| 久坐提醒 | 设置提醒间隔（30-60 分钟） | 定时提醒 + 推荐微休息方案 | 提醒工具只提醒不推荐 |
| 查看进度 | 查看周/月统计、连续打卡天数 | 看到改善趋势、获得正向反馈 | 坚持不下来、无反馈 |
| 高风险评估 | 评估命中安全红线 | 弹出就医提示，不推荐方案 | 怕动错加重不适 |

### 2.3 专业壁垒

由SUS 运动康复专业学生开发专业内容，所有方案基于运动康复教科书和临床指南编写，经专业教师审核。通过 CodeArts Skills 将专业评估规则和方案匹配逻辑封装为可编程能力，实现"运动康复知识可编程化"。

## 3. 功能需求

### 3.1 功能清单与优先级

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F1 | 用户注册/登录 | 匿名 ID 或手机号注册，JWT 鉴权 | P0 |
| F2 | 体态自评问卷 | 肩颈+腰背两区域问卷，提交生成评估报告 | P0 |
| F3 | 分场景运动方案推荐 | 根据评估结果+场景参数匹配推荐 3 个方案 | P0 |
| F4 | 久坐提醒设置 | 自定义提醒间隔，浏览器通知/页面弹窗 | P0 |
| F5 | 训练进度追踪 | 记录完成方案/时长/日期，周月统计+打卡天数 | P0 |
| F6 | 就医提示红线 | 高风险评估强制就医提示，不推荐方案 | P0 |
| F7 | 智能问答 | 基于知识库的常见问题回答 | P1 |
| F8 | 数据可视化 | 体态改善趋势图、部位关注度热力图 | P1 |
| F9 | 方案收藏与自定义 | 收藏方案、调整提醒频率 | P1 |

### 3.2 功能详细需求

#### F2 体态自评问卷（P0）

| 子需求 | 说明 |
|---|---|
| 分区评估 | 肩颈区 8 题 + 腰背区 8 题，独立评估不混合 |
| 多维度覆盖 | 每区域覆盖：疼痛频率、僵硬程度、活动受限、姿势习惯 |
| 量化评分 | 每题 0-3 分（无/偶尔/经常/持续），区域总分映射风险等级 |
| 安全红线 | 特定条目高分（放射性疼痛/下肢麻木）直接触发就医提示 |
| 风险等级 | 低风险(0-5分)→预防方案；中风险(6-12分)→干预方案；高风险(13-18分)→就医提示 |
| 评估报告 | 展示风险等级 + 主要问题点 + 个性化建议 + 推荐方案入口 |

#### F3 分场景运动方案推荐（P0）

| 子需求 | 说明 |
|---|---|
| 场景选择器 | 时间（3/5/10/15分钟）× 部位（肩颈/腰背/全身）× 场景（办公桌/站立/居家） |
| 匹配逻辑 | 评估结果（风险等级+问题部位）+ 场景参数 → 按匹配度排序推荐 3 个方案 |
| 方案详情 | 动作序列（名称+描述+时长+图示URL）、注意事项、禁忌人群 |
| 方案库规模 | 36+ 方案单元，200+ 动作条目 |
| 安全过滤 | 根据评估结果自动过滤不适合方案（如颈椎急性期禁做颈部环绕） |

#### F5 训练进度追踪（P0）

| 子需求 | 说明 |
|---|---|
| 训练记录 | 每次完成方案记录：plan_id、实际时长、完成时间 |
| 打卡天数 | 连续完成方案的天数，首页展示 |
| 周统计 | 本周完成方案次数、总时长、涉及部位 |
| 月统计 | 本月完成趋势、部位关注度分布 |
| 改善趋势 | 历次评估风险等级变化趋势（P1 可视化） |

## 4. 技术架构

### 4.1 整体架构

```
┌─────────────────────────────────────────┐
│              前端（Vue3 + Element Plus）          │
│  评估页 │ 方案推荐页 │ 提醒追踪页 │ 我的页 │ 首页  │
└──────────────────┬──────────────────────┘
                   │ HTTP / JWT
┌──────────────────┴──────────────────────┐
│            后端（FastAPI + uvicorn）              │
│  auth │ assessment │ plan │ reminder │ training  │
├──────────────────────────────────────────┤
│          CodeArts Skills（4 个自定义）            │
│  posture_assessment │ plan_matcher │ safety_check │ qa_responder │
├──────────────┬───────────────────────────┤
│  RDS MySQL   │      DCS Redis            │
│  6 张核心表   │  方案缓存/会话/打卡/问答    │
└──────────────┴───────────────────────────┘
```

### 4.2 CodeArts 自定义 Skills

| Skill | 输入 | 输出 | 实现 |
|---|---|---|---|
| posture_assessment | 问卷答案 JSON | 风险等级 + 问题点 + 建议 | Python 规则匹配 + 加权评分 |
| plan_matcher | 评估结果 + 场景参数 | 推荐方案列表（3个，按匹配度排序） | Python 规则匹配 + 加权排序 |
| safety_check | 评估结果 + 用户信息 | 安全判定 + 是否就医 | Python 规则判断 |
| qa_responder | 用户问题文本 | 知识库答案 + 相关方案 | Python 关键词匹配 |

### 4.3 RDS 数据表设计（6 张）

| 表名 | 核心字段 | 说明 |
|---|---|---|
| user | user_id, nickname, phone, age, occupation, history | 用户档案 |
| assessment | assessment_id, user_id, area, answers(JSON), risk_level, problem_points(JSON), suggestion | 评估记录 |
| exercise_plan | plan_id, name, duration_min, target_area, scene, movements(JSON), suitable_level, contraindication | 运动方案库 |
| training_log | log_id, user_id, plan_id, duration_actual, completed, created_at | 训练记录 |
| reminder_setting | reminder_id, user_id, interval_min, active_hours, enabled | 提醒设置 |
| knowledge_base | kb_id, question, answer, keywords, related_plans(JSON), category | 知识库 |

### 4.4 Redis 缓存设计

| Key 模式 | 结构 | TTL | 用途 |
|---|---|---|---|
| plans:hot:{area}:{duration} | Hash | 1h | 热门方案缓存 |
| qa:cache:{question_hash} | String | 24h | 问答结果缓存 |
| user:session:{user_id} | Hash | 30min | 问卷分步提交中间状态 |
| user:streak:{user_id} | String | 24h | 连续打卡天数 |

## 5. 页面规划与交互流程

### 5.1 页面清单（初赛 6 页）

| 页面 | 核心元素 | 优先级 |
|---|---|---|
| 首页 | 功能导航、快速评估入口、今日推荐方案、打卡天数 | P0 |
| 体态评估页 | 分步问卷（肩颈区→腰背区）、评估报告展示 | P0 |
| 方案推荐页 | 场景选择器、方案卡片列表、方案详情（动作序列） | P0 |
| 提醒与追踪页 | 提醒设置、训练日历、周月统计 | P0 |
| 我的页 | 评估历史、训练记录、个人信息 | P0 |
| 智能问答页 | 问答输入框、答案展示、相关方案推荐 | P1 |

### 5.2 核心交互流程（P0 闭环）

```
注册/登录
  → 体态自评（肩颈8题 + 腰背8题，约3分钟）
  → 评估报告（风险等级 + 问题点 + 建议）
  → [高风险] → 就医提示，结束
  → [低/中风险] → 方案推荐（选场景→3个方案）
  → 方案详情（动作序列跟练）
  → 完成打卡（记录时长）
  → 进度追踪（打卡天数 + 周月统计）
  → 久坐提醒设置（间隔 + 时段）
```

### 5.3 设计风格

黑白灰极简配色（#1f1f1f / #f5f5f5）+ 卡片式布局，强调专业感和清爽感。移动端优先，单手可操作。

## 6. 验收标准

| 编号 | 验收项 | 标准 |

## 8. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 评估提交→报告 < 3 秒；方案推荐 < 1 秒；页面加载 < 2 秒 |

| 合规 | 全局免责声明；高风险就医提示；不使用"诊断/治疗"等医疗术语 |
| 兼容 | Chrome/Safari/Edge 主流浏览器；移动端优先响应式 |
| 可维护 | 前后端分离；API 文档完整；方案库可扩展 |
